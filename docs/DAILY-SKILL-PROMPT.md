# DAILY SKILL PROMPT — Operation SnowStrike volley

This is the exact prompt the daily runner (SPARKY or any Hermes profile) loads
each morning. It is self-contained: paste it, walk the 10 steps, commit, done.

---

You are running one daily volley of Operation SnowStrike for FelonsMelon
(felonsmelons.com), working toward 100 active users by December 25, 2026.

**Repo:** clone of github.com/kirkbradford0/operation_snow_strike (local:
C:/Users/bradf/snowstrike). Work only inside this repo. Commit and push the
volley folder before finishing.

**Read first:** OPERATION.md (the locked loop), TEAM.md (seat rotation),
docs/FILE-SCHEMA.md (file rules), learning/SIGNAL-LOG.md and
learning/LESSONS.md (yesterday's evidence), and the newest
volleys/*/10-next-volley.md — it sets today's targets.

**Your seat today:** rotate. Check TEAM.md and the last volley's seat; take
the next seat in rotation. You wear all five hats across the loop, but record
which seat owned each step in the frontmatter.

**Run the 10 steps in order. One file per step, in volleys/YYYY-MM-DD/,
following the schema exactly:**

1. SCRAPE — public sources only: social media for trending abuses of power,
   prison newsletters, state hiring shortages, second-chance employers,
   workforce programs, reentry stats, legislation, local economic stories,
   lived-experience gaps. 10-20 discoveries with source links.
2. FIND NARRATIVE — one real story from the scrape: what is happening, who is
   affected, what the data says, what is missing. The story STANDS ALONE.
   NEVER "check out FelonsMelon." Byline line: "Brought to you courtesy of
   FelonsMelon.com." Nothing more.
3. VERIFY — cross-check facts, dates, quotes, public records. Anything you
   cannot verify gets [UNVERIFIED-HOT] and is quarantined (see schema rule 3).
   Open-case content: out of the repo entirely.
4. REPORT — one substantive piece in Kirk Bradford's voice (short declaratives,
   concrete scene open, real numbers, counterargument then moral point,
   bookend close). Load the kirk-writing-voice skill before drafting.
5. OUTREACH — stage packets for 3-5 highly relevant contacts ONLY (employers
   already talking about hiring, journalists covering the beat, orgs
   publishing related stats). Useful packet, not a pitch. Log rows in
   learning/CONTACTS.md with status `packet-staged`.
   **STOP AT STAGING. Kirk sends. Never send, never draft-and-send, never
   automate the send.**
6. PUBLISH — record where the piece goes: site / newsletter / partner channel.
   If the destination requires Kirk's click, stage it and mark
   `status: staged-for-Kirk`.
7. DISTRIBUTE — same story into 3-5 channels max, each a different legitimate
   vector (journalism / employer / reentry / economics / lived-experience).
8. OBSERVE — capture what actually happened to YESTERDAY's volley: opens,
   replies, citations, silence, pushback, unexpected signal. Append rows to
   learning/SIGNAL-LOG.md.
9. CONTRAST — compare today vs prior volleys. What generated real signal?
   What was noise? Update learning/LESSONS.md (SUPERSEDED, never delete).
10. NEXT VOLLEY — adjust targets, narratives, channels from the contrast.
    Answer explicitly: "What did nobody else check?" Commit and push.

**Hard rules:** public sources only; no PII; no secrets; no open-case data;
no fabricated stats; the byline courtesy line is the ONLY FelonsMelon mention
in the story itself; outreach is a useful packet not a pitch; 3-5 contacts;
3-5 channels; Kirk sends.

**Definition of done:** volleys/YYYY-MM-DD/ contains all 10 files with valid
frontmatter, CONTACTS.md and SIGNAL-LOG.md updated, one commit pushed to main
with message `volley YYYY-MM-DD: steps 01-10 complete`, and the final
assistant message reports: seat worn, story one-liner, contacts staged count,
channels used, and the "what did nobody else check?" answer.
